MGVC decoder

Panasonic’s Master Grade Video Coding puts 12-bit video on a Blu-ray in a way ordinary players can ignore: a normal 8-bit picture, plus enhancement data only Panasonic’s players use. These tools rebuild the 12-bit frames without one.

Languages
Python for the reference implementation and tests, C for the native converter
Built on
edge264-mvc and mvc-source for MVC decoding
Source
github.com/Zachgille/mgvc-decoder

Where the extra bits are

An MGVC disc uses the same multiview coding (MVC) that 3D Blu-rays use for the second eye. Instead of a second view of the scene, the dependent view carries corrections for the first. A mapping file on the disc, EDL.bin, describes how the virtual streams fit together.

I worked from Panasonic’s Japanese release of The Wind Rises (VWBS-1531), Panasonic’s patent US9392246B2, and the bitstreams themselves. On this disc, the per-frame shift values turned up inside nested SEI messages in the MVC stream:

The arithmetic

Each 12-bit sample is the 8-bit base sample moved up four bits, plus a correction from the enhancement view. The base layer went through a lossy encode, so it isn’t simply the original’s top eight bits. The correction has to carry that error too, which is why it’s a full byte rather than the four missing bits.

On the disc, corrections are stored centered on 127 so they can be negative, and the frame’s shift value decides how far the correction is moved before it’s added:

Two implementations

The Python version in mgvc_core.py is the reference. It parses the disc mapping, does the sample arithmetic one value at a time, counts clipped samples, and is covered by unit tests on synthetic fixtures.

Pure Python is too slow for a feature-length film, so the native converter applies the same per-component shifts in C to paired views decoded by edge264-mvc, and streams the result to disk or straight into an encoder. It treats the shift map as evidence that has to be checked: a full conversion refuses a map that isn’t marked verified.

Where it stands

The reference implementation, the metadata extractor, the native converter and their tests are in the repository. I haven’t yet finished an end-to-end encode to 12-bit HEVC in MKV with the disc’s audio, subtitles and chapters, which is the goal.

The repository contains source code and synthetic test data only. No disc content, encoded video or third-party binaries.
