Engineering case study / Android TV

AtlasTV

A media client for a directional remote. Browse a local catalog, find an episode, and return to the point where playback stopped.

Kotlin · Jetpack Compose · Room
AndroidX Media3 · Coroutines

Sixteen shelves, less waiting.

The Movies and Shows screens each needed eight genre previews. Independent queries repeated the same eligibility and variant checks. I grouped the candidates in SQLite, then materialized only the winning titles for each shelf.

Across three paired runs, all sixteen shelves returned the same items in the same order. Cold-launch medians were effectively unchanged, which narrowed the next investigation to artwork loading.

What gets the next download?

A poster entering the viewport can move ahead of queued prefetch work. Two cards that need the same image share a request when the existing decode is large enough. When the last subscriber leaves, the download can be canceled.

Retry from the same frame

A viewer who rewinds and then loses the connection should keep that new position. AtlasTV retains the playback checkpoint while retrying an eligible failure against a configured backup endpoint. Device tests exercised movie and episode recovery from a saved 255-second position.
