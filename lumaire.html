Lumaire

A media client for Android TV, built around a directional remote: browse movies and series, search a local catalog, keep a watchlist, and pick up where playback stopped.

Stack
Kotlin, Jetpack Compose, Room/SQLite, AndroidX Media3, coroutines
Tested on
An Onn TV box, plus JVM and instrumentation tests
Source
github.com/Zachgille/AtlasTV

Sixteen shelves, one query

The Movies and Series screens each open with eight genre shelves. Originally every shelf ran its own query, and every one of those queries did the same groundwork: join the discovery metadata to the catalog, drop duplicate variants of the same title, and work out a trusted rating (an IMDb rating only counts once it has 1,000 votes). On a TV box that adds up, and with a remote in your hand you feel every pause between shelves.

I moved the groundwork into one common table expression that all eight shelves read from. Each shelf takes its top titles from that shared candidate set, and only the winners leave SQLite to be loaded as full catalog rows.

The obvious tool here would be a window function, ranking titles within each genre, but the query has to run on the SQLite versions that ship with older Android TV devices. A shared CTE avoids that, and because nothing is stored there’s no cache to invalidate when the catalog refreshes.

Measuring on the box

I compared both versions on the device itself, an inexpensive Onn TV box, in three paired runs. All sixteen shelves came back with the same titles in the same order, and the median combined query time dropped by 40%.

Cold-launch time barely moved. The queries had been a real cost, but not the one holding up the first screen, which pointed the next round of work at artwork.

Posters first

A shelf of posters is mostly image loading. Lumaire schedules it with a few rules:

  • A poster scrolling into view jumps ahead of queued prefetch work.
  • Two cards that need the same image share one download and decode, as long as the existing decode is large enough for both.
  • If every card waiting on a download goes away, the download is cancelled.
  • Disk-cache reads and network fetches have separate concurrency limits, so images already on disk don’t wait behind slow downloads.

When the stream drops

If you rewind and then the connection fails, playback should resume from where you rewound to, not from the last saved checkpoint. On a retryable failure, Lumaire can switch to a configured backup endpoint while keeping the selected episode and the current position. Authentication and codec errors take their own recovery paths instead of being retried.

Device tests cover recovery for both movies and episodes, resuming from a saved position 255 seconds in.

What’s in the repo

Lumaire doesn’t include any content. You point it at a media source you’re authorized to use, and discovery metadata (genres and ratings) comes from IMDb’s non-commercial datasets, prepared locally by a script. The repository has JVM unit tests, Android instrumentation tests, exported Room schemas and synthetic parser fixtures. Account settings and device diagnostics stay out of it.

The project was called AtlasTV until recently, so the repository and package names still use the old name.
